# STEP 3: JSON FORMATTER
## WPAgent v3.20.1 — WordPress Import Format

## DISTRIBUTION MODEL: ThemeForest
This theme is sold on ThemeForest (Envato Market).
RULES:
- Primary marketplace source: ThemeForest
- "sales_count" = ThemeForest total sales
- external_ratings: ThemeForest rating is primary

## CRITICAL:
1. Output ONLY valid JSON
2. NO markdown, NO explanation
3. Use [1], [2] format for IDs
4. NO [ID] in quick_verdict, summary_paragraphs
5. NO null values — use "" or 0
6. Gutenberg format for summary_paragraphs
7. ALL verdict fields MUST be full sentences (20+ words) or empty string
8. performance_metrics MUST be populated from pagespeed_data if available
9. performance_tier MUST match pagespeed_mobile score
10. Map input fields: lcp_score→lcp_mobile, cls_score→cls_mobile, tested_url→test_url, pagespeed_insights_link→pagespeed_link
11. handoff_score: Set to 0 - calculated automatically in post-processing
12. SOURCE INTEGRITY (CRITICAL):
    a. The sources array MUST contain EVERY URL referenced anywhere in the JSON
    b. Every [N] in any field (source, user_issues, faq_answer) MUST have matching entry in sources
    c. Every community_pain_point source_url MUST appear in sources array
    d. Use consecutive numbering [1],[2],[3]... with NO gaps
    e. Copy ALL sources from Step 1/Step 2 — do NOT drop any
    f. Post-processing will fix numbering, but sources MUST be COMPLETE
13. distribution_model MUST be set to "${distribution_model}"
14. search_profile: Leave as empty string "" — generated automatically in post-processing
15. PLUGIN COMPAT INTEGRITY: plugin_compatibility_list in output MUST include every plugin
    that appears in community_pain_points. If a pain point names a plugin, that plugin
    must have an entry in plugin_compatibility_list. Do not drop any entries from Step 2.
16. version_reported: For each community_pain_point, include the theme version from the
    source thread/article. Use "unknown" if not mentioned in the source.
17. community_praise_stats: MUST contain at least 3 entries from Step 1/Step 2 praise.
    Each entry needs: category, positive_aspect, strength, title, description, source, source_url.
    Do NOT output an empty praise array if Step 1/Step 2 contain praise points.
18. scope: For each community_pain_point and community_praise_stat, set to "theme", "blocks", or "ecosystem" based on Step 1 [THEME]/[BLOCKS]/[ECOSYSTEM] tags. Default: "theme".
19. date_reported: For each community_pain_point, set YYYY-MM from Step 1 Date Reported column. Use "date-unknown" if not available.
20. source_date: For each source in sources array, set YYYY-MM from Step 1 Sources Index Date column.
21. source_date ENFORCEMENT: Every source in the sources array MUST have source_date populated. Extract from Step 1 Sources Index Date column. This field is MANDATORY — do not leave it empty.
22. community_timeframe MUST be set to "Last 6 months" — this is the analysis window.
